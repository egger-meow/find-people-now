# Find People Now：iOS 優先核心旅程 UI/UX 改版設計

日期：2026-08-11  
狀態：已確認設計方向，待規格審閱  
範圍：探索／首頁 → 建立配對 → 等待與確認 → 活動詳情

## 1. 目標

將核心旅程提升為以 iPhone 使用者為主的「Calm Glass Hybrid」體驗：內容層保持安靜、清楚、易讀，只在導航、關鍵狀態與主要行動使用適量半透明與景深效果。整體感受參考 ChatGPT iOS 的克制、iOS 26 的流動層次，以及 Aether 的柔和光感，但不照搬其品牌、文案或過度裝飾。

本次改版的成功條件：

- 使用者能更快辨認目前狀態、下一步與主要操作。
- 核心流程的資訊密度下降，但功能、規則與必要文字完全保留。
- 繁體中文是正式介面語言，不以英文樣稿取代現有文案。
- iOS 上具有一致的安全區、返回行為、觸覺回饋、底部分頁與動態感。
- Android 仍維持可用與一致的資訊架構，不因 iOS 視覺優先而退化。

## 2. 不可破壞的產品約束

### 2.1 功能與文字完整性

- 不刪除現有功能、操作入口、狀態、錯誤訊息、限制條件或安全說明。
- 不刪除會影響使用者決策的文字，包括時間範圍、校區、人數、能力條件、降級配對、等待期限、確認期限、邀請、離開、取消、檢舉與封鎖相關說明。
- 既有繁體中文文案必須保留其完整語意。若調整，只能改善標題、分段、順序、標點或可讀性。
- 圖示不可取代必要文字；圖示型按鈕須有語意標籤與輔助使用說明。
- 任何收合或漸進揭露的內容都必須有清楚、可見、可點擊的入口，且不得只靠手勢或 hover。

### 2.2 可簡化內容

僅能簡化下列非關鍵呈現：

- 同一畫面重複出現且語意相同的提示。
- 在使用者尚未完成前一步時，無需立即操作的進階選項。
- 可由清楚摘要取代的重複明細；完整明細仍保留於展開區或確認區。
- 純裝飾性區塊、無資訊價值的卡片包裝與過多分隔容器。

## 3. 視覺系統

### 3.1 風格

- 採用「安靜內容面＋選擇性玻璃層」。一般閱讀內容不大量玻璃化。
- 玻璃材質只用於底部分頁、浮動主要行動、關鍵狀態摘要、sheet 與必要的前景控制。
- 背景使用非常淡的品牌光暈或 tonal gradient，不使用大面積紫粉 AI 漸層。
- 卡片數量減少；資訊群組優先使用留白、標題、細分隔線與清楚對齊建立層級。
- 保留既有校園、即時、人本品牌感，避免企業 SaaS、遊戲化或過度科幻外觀。

### 3.2 色彩

- 延續既有綠色作為品牌與成功／進行中識別，避免整體改成樣稿中的紫色品牌。
- 新增語意化 surface、glass、hairline、shadow、focus 與 status token，元件內不得散落臨時色碼。
- Light mode 採暖白／中性淺灰內容面；Dark mode 採接近黑色的中性內容面，而非純黑與高飽和霓虹。
- 玻璃層在 light/dark 皆須有足夠實色底與細邊界，不得因透明而降低文字對比。
- 一般文字對比至少 4.5:1；大型文字與主要圖示至少 3:1。

### 3.3 字體與層級

- iOS 優先使用系統中文字體，保持與 SF Pro／PingFang TC 的原生一致性；不額外載入網路字體。
- 繁中內文基準不小於 16 logical pixels；輔助資訊原則上不小於 13。
- 標題減少過重粗體，主要使用 500–600，讓層級由尺寸、留白與位置共同建立。
- 支援 Dynamic Type／文字縮放；關鍵文字不得以固定單行截斷。

### 3.4 形狀、間距與景深

- 使用 4／8pt 節奏；核心間距以 8、12、16、24、32 為主。
- 觸控目標至少 44×44pt，相鄰觸控區至少保留 8pt。
- 一般內容面圓角約 16–20；浮動玻璃層約 20–28；主要按鈕可使用膠囊或 16–18 圓角，但同一層級保持一致。
- 景深以柔和陰影、hairline 與 blur 共同表現，不使用多層厚重陰影。

## 4. 導航與共用元件

### 4.1 App Shell

- 保留目前四個底部分頁與所有 badge、路由及狀態更新行為。
- iOS 底部分頁改為安全區內的 calm-glass bar；選取狀態同時使用圖示、文字與色彩，不只靠色彩。
- 不阻擋系統返回手勢，不把主要內容藏在 home indicator 或 tab bar 後方。
- Android 延續 Material NavigationBar，但共享相同的語意 token、資訊層級與觸控尺寸。

### 4.2 共用元件

在既有 `AppCard`、`AppButton`、`AppSheet`、`AppDialog`、`AppTextField` 與 adaptive 元件上擴充，不建立互不一致的一次性元件。

需要的元件角色：

- `AppGlassSurface`：只供前景、浮動或狀態層使用。
- `AppSection`：以標題、說明、間距與可選分隔線組織內容，減少卡片濫用。
- `AppStatusSummary`：顯示目前狀態、期限、進度與下一步。
- `AppStickyActionArea`：尊重鍵盤與安全區的主要行動區。
- `AppSelectionSummary`：在漸進流程持續顯示已選活動、時間、校區、人數與其他條件。

所有非同步操作須保留 loading、disabled、成功與錯誤回饋，不能因改版造成重複送出。

## 5. 核心畫面設計

### 5.1 探索／首頁

- 頂部先呈現目前最重要的使用者狀態：可建立配對、正在等待、待確認或已有活動。
- 主要 CTA 使用完整繁中動詞，例如「開始建立配對」或對應既有文案，不使用只有加號的入口。
- 校園即時資訊與即將到來的活動採安靜列表／摘要，不為每一項建立厚重卡片。
- 若使用者已有進行中流程，首頁優先顯示「繼續」與必要期限，不以新配對 CTA 搶走層級。

### 5.2 建立配對

- 保留所有現有欄位與條件：活動、能力／目標條件、時間、校區、人數、降級配對及錯誤訊息。
- 流程以單頁漸進分區呈現，不改為容易迷失的多頁 wizard。
- 只有依前一步選擇才適用的選項可延後顯示；已經適用的重要限制必須直接可見。
- 頂部或適當位置持續顯示選擇摘要；頁尾在送出前顯示完整繁中確認內容。
- 主要送出行動可在可操作後固定於安全區上方；disabled 狀態須同時說明尚缺少的條件。
- 鍵盤、sheet 與選擇器開啟時，焦點欄位及錯誤不得被固定行動區遮住。

### 5.3 等待與確認

- 以單一 `AppStatusSummary` 清楚呈現「目前正在做什麼、剩餘時間、目前人數、接下來會發生什麼」。
- 等待動畫僅作狀態輔助，不取代文字；使用者啟用減少動態時停止裝飾性循環。
- 配對條件完整保留於摘要／明細區；邀請碼、複製、撤銷、離開與取消功能全部保留。
- 危險操作維持二次確認，並清楚描述後果。
- REQUESTING、PENDING_CONFIRMATION、MATCHED、EXPIRED、CANCELLED 等狀態使用一致的圖示、標題、說明與主要行動模式。

### 5.4 活動詳情

- 第一屏優先顯示活動狀態、時間、地點／投票結果與下一個必要操作。
- 成員、地點提案／投票、集合點、抵達確認、聯絡資訊、完成回報、封鎖與檢舉等既有功能全部保留。
- 將低頻管理操作放入明確標示的次要區或 action sheet；不得從介面移除。
- 使用 section 與狀態摘要降低卡片堆疊，長說明以段落與小標改善閱讀。
- 對即將開始、等待投票、需要抵達確認等時效狀態，固定提供明確中文下一步。

## 6. 動態與觸覺

- 一般 micro-interaction 為 150–250ms；進入 ease-out、離開稍快。
- 每個畫面最多只有 1–2 個重點動態，不使用持續漂浮、裝飾性 bounce 或大範圍視差。
- 主要按壓提供穩定的 opacity／scale／surface 回饋與既有 haptic，不造成排版位移。
- 路由維持 iOS 原生返回轉場與 Android 適配轉場。
- 完整尊重 `MediaQuery.disableAnimations`；等待狀態仍以靜態文字與進度資訊成立。

## 7. 無障礙與韌性

- VoiceOver／TalkBack 閱讀順序須與視覺順序一致。
- 圖示按鈕、badge、selected、disabled、expanded 與 loading 狀態提供正確 semantics。
- 支援 200% 文字縮放；文字可換行，主要操作不能被擠出畫面。
- iPhone 小尺寸、一般尺寸、Max 尺寸與橫向皆不得水平溢位。
- loading 使用 skeleton 或明確指示；error 在問題附近呈現，並保留可重試路徑。
- 色彩不可是唯一狀態識別方式。

## 8. 技術邊界

- 本次不修改 Supabase schema、RPC、matching 邏輯或產品狀態機。
- 不重新命名或刪除路由，不移除既有 provider 與 side effect。
- 優先改造 theme token、adaptive shell 與共用 widget，再逐頁套用，避免畫面間漂移。
- 若現有單一 screen 過長，可在不改變資料流的前提下拆出純展示區塊；不進行無關的架構重寫。

## 9. 驗收與測試

### 9.1 功能回歸

- 既有 widget、smoke 與 integration tests 全部通過。
- 對四段核心旅程建立或更新 widget tests，覆蓋主要狀態、按鈕、錯誤、loading 與危險操作確認。
- 建立「既有關鍵中文文案／功能入口仍存在」的回歸檢查，避免視覺整理時誤刪。

### 9.2 視覺與裝置

- 至少驗證 375pt 小型 iPhone、一般 iPhone、Max／大字體與橫向。
- Light／Dark mode 各自檢查對比、邊界與 glass 可讀性。
- 驗證 safe area、鍵盤、底部分頁與 sticky CTA 不遮蔽內容。
- 驗證 reduced motion 與 200% 文字縮放。

### 9.3 完成定義

- 核心旅程視覺一致，且沒有新增一次性顏色、圓角或間距值。
- 所有既有功能與關鍵繁中語意可被使用者找到並完成。
- 沒有因收合、玻璃、固定行動區或動畫造成的可用性與無障礙退化。
- Flutter analyzer 與相關測試通過，並完成實機或模擬器視覺檢查。

## 10. 明確不在本次範圍

- 非核心頁面的全面重設，例如完整個人檔案、通知中心、回饋與說明頁。
- 後端功能、配對演算法、資料庫與產品規則變更。
- 新增語言切換或改寫整套產品文案。
- 大量插畫、3D、粒子、沉浸式背景或高成本持續動畫。
